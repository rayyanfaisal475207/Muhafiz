# ============================================================
# requirements.lock.txt — Reproducible install for CI/deployment
#
# requirements.txt remains the floor-pinned INTENT file (>= bounds,
# for readability/onboarding). This file is what CI actually installs
# from (`pip install -r requirements.lock.txt`), so a build today and
# a build next year resolve to the exact same versions.
#
# PROVENANCE: this was NOT generated with a plain `pip freeze` in a
# dedicated venv — this project's only available Python environment
# is a large shared/global install (290+ packages, most unrelated to
# this project). Instead, this file is the transitive dependency
# closure of requirements.txt's direct packages, computed from that
# same environment's already-installed metadata (no new installs),
# scoped down to just what this project actually needs.
#
# KNOWN GAP: computed on Windows; CI runs on ubuntu-latest.
#   - Windows-only conditional deps (pywin32, pyreadline3 — pulled in
#     transitively by docling-parse/mcp/humanfriendly on sys_platform
#     == "win32") are deliberately EXCLUDED here — pinning them would
#     make `pip install` hard-fail on Linux, since they have no
#     Linux wheels at all.
#   - uvloop (uvicorn[standard]'s Linux/Mac performance extra) is NOT
#     installed on this Windows machine, so its version could not be
#     read from local metadata and is NOT pinned below. CI will
#     install whatever uvloop version is latest-compatible at install
#     time — the one deliberate exception to full reproducibility in
#     this file. Non-fatal (uvicorn runs fine without it, just with
#     the standard asyncio loop instead of the faster one) but worth
#     fixing properly the first time this lockfile is regenerated
#     from an actual Linux environment (e.g. inside CI itself).
#
# Regenerate on a real dependency bump by re-running this same
# closure computation (or switch to pip-tools/poetry per solution.md
# Module 11.3, which was explicitly left as a team choice, not
# decided here).
#
# ADDENDUM (Module 11.4 — CI coverage reporting): pytest-cov and its
# coverage dependency are NOT installed on this machine either
# (same no-new-installs constraint as the rest of this file), so
# their pins below came from a PyPI lookup of latest-stable at the
# time this was written (pytest-cov 7.1.0, which itself requires
# coverage>=7.10.6; coverage 7.15.2 satisfies that), not from local
# metadata like every other line in this file. Re-verify both on the
# next real regeneration.
# ============================================================
